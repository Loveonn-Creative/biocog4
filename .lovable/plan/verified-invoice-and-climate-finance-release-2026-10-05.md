# Verified invoice and climate-finance release

## Outcome
Make each signed-in invoice's evidence and verification state intelligible and consistent across History, Verify, Dashboard, MRV, Reports, MONETIZE, and Settings. Add useful financial-risk context only where real source documents and supported calculations justify it. Keep guest behavior, existing carbon methodology and factors, checkout, and live records intact.

## Release gates
1. **Audit before changing live data.** Inventory existing signed-in invoices, extracted rows, source files, ownership, verification memberships, ledger duplicates, and downstream discrepancies. Classify each invoice as verified and consistent, ready to verify, missing inputs, failed extraction, or requiring human review. Inspect existing policies and deployment state. Do not overwrite historic attempts or treat cached extraction as verified evidence.
2. **Complete evidence-gated bulk verification.** Reuse the current verification function's inspection mode for per-invoice missing-input results. Present a signed-in bulk action that submits only fully evidenced, owned emissions in bounded batches, with a per-invoice outcome and retry for genuine failures. Keep inspection read-only. Make the commit atomic/idempotent under concurrent requests, including its verified flags and audit linkage; never silently create a success when a ledger write fails. Do not recalculate missing invoices, copy another document's figures, or auto-approve unsupported records. Maintain the existing guest path. Remove the fabricated client-side rejection and unsupported monetary preview from Verify.
3. **Make Refresh a real reconciliation read.** On History and Verify, refetch authorized documents, emission IDs, verification evidence and ledger links, compare each invoice's state, and visibly identify missing or inconsistent coverage. Refresh itself creates no invoices, emissions, verifications, credits or financial values. Align Dashboard, MRV, Reports, MONETIZE and Profile with the same distinct verified emission IDs and matching evidence; invalidate/refetch on successful verification and revisit. Deduplicate historical read results without deleting audit history.
4. **Extend evidence handling for finance without inventing decisions.** Audit the existing energy-bill and financial-document intake before modifying it. Parse explicit bill units, dates, meter readings, currency and monetary fields with their source locations and confidence; keep consumption separate from billed money, and flag ambiguous units or unreadable values. Where an ITR or related financial document is supplied, capture only explicit, relevant fields in a private, owner-scoped evidence record with source references; no tax inference, automatic creditworthiness, underwriting, interest discounts, advance rates, subsidies, partner delivery or approvals. Reuse the existing extraction/storage path where safe; add a narrowly scoped migration with grants/RLS only if the existing schema cannot protect and represent that evidence. Do not feed financial documents into carbon emissions by default.
5. **Ground the finance and risk view.** Replace the current fixed rupee/loan/factoring projections and unsupported application claims with mathematically reproducible indicators derived from distinct verified evidence and explicit user-provided financial inputs, displaying units, periods, missing inputs, uncertainty and source links. Keep observed verification quality separate from lender eligibility or any decision made outside Senseible; hide unsupported totals and charts instead of estimating them. Reuse credibility and trust views where their inputs can be traced, and prevent duplicate ledger rows from inflating financial sums. Basic/Snapshot/Essential get a concise evidence and gap view by default; Pro/Scale can opt into detailed metrics and audit trails using one Settings toggle backed by authenticated tier checks, not client storage as authorization. Preserve an honest basic view when opted out.
6. **Release only after passing gates.** Add regression tests for bill/ITR parsing, units and source references, missing evidence, duplicate historical links, concurrent bulk verification, ownership, tier/toggle behavior, and read-only repeated Refresh. Test with a signed-in account and real saved invoices through History → Verify → Refresh → Dashboard/MRV/Reports/MONETIZE/Settings; compare IDs, totals and database row counts before/after two Refreshes. Exercise guest and lower-tier paths for regressions. Deploy only changed functions/migrations after checks, verify deployed responses and current live data, and report each invoice category plus any blocked review rather than claiming every historical invoice verified. Fix the existing Profile password flow and reviewed-language fallback as part of the unfinished authenticated reliability work, without unrelated redesign.

## Technical boundaries
The current verification function has an undeployed `inspectOnly` evidence gate, while History Refresh only reloads documents/emissions. Signed-in storage currently includes documents without extraction or hash, and linked emissions missing core inputs; these require source review rather than automatic verification. Existing verification records can repeat emission membership. Keep carbon math and factor versions unchanged. Finance evidence must remain private and access-controlled; no public financial records, new credit promises, or simulated integrations. Do not publish a frontend change or claim a successful live release until the authenticated end-to-end checks pass.
